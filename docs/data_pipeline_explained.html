What Changed in the Folk Tales Training Pipeline

A plain-English walkthrough of how the project now downloads the folklore dataset, prepares it for language-model training, trains a small tokenizer, and verifies that the training code can read the data.

Big Picture What Changed Parameters What Was Tested Glossary Commands

Big Picture

You want to train a language model on the Hugging Face dataset merve/folk-mythology-tales. A language model cannot train directly from a web page. The project needs a repeatable path that turns that web dataset into local files the training code can stream.

That path is called the data pipeline. In this repo, the data pipeline lives mostly in prepare.py. Its job is to download the dataset, make a train/validation split, train a tokenizer, and expose a dataloader that train.py can use.

Simple version: I changed prepare.py so the project uses the folk tales dataset instead of the old default dataset, then I ran the preparation and a real training run to make sure the pieces worked together.

What Changed

  1. Pointed the project at the new dataset

    The original code was configured for a different Hugging Face dataset: karpathy/climbmix-400b-shuffle. I changed it to use: merve/folk-mythology-tales.

  2. Changed how the data is downloaded

    The old dataset was arranged as thousands of files named like shard_00000.parquet. The folk tales dataset is different: Hugging Face provides one converted Parquet file for its train split. I updated the code to ask Hugging Face for the correct Parquet download URL instead of guessing file names.

  3. Created a local train/validation split

    The dataset only comes with a train split. For model work, we also need a val split. Training data teaches the model; validation data checks whether the model is learning patterns that generalize beyond the exact text it trained on.

    I made prepare.py reserve 5% of the rows for validation and use the other 95% for training.

  4. Kept only the text column

    The model trains on text. The preparation step now confirms that the dataset has a text column, removes empty text rows, and writes clean local Parquet files.

  5. Moved the cache into a dataset-specific folder

    The prepared files are stored under ~/.cache/autoresearch/folk-mythology-tales/. This avoids mixing the folk tales data and tokenizer with data from another experiment.

  6. Protected the training code from reading the wrong file

    The downloaded raw file is kept as raw_train.parquet, but the dataloader now only lists train.parquet and val.parquet. That prevents accidental double-counting or training on the raw file.

Parameters and Settings

A parameter is a setting that controls behavior. These are the important ones involved in the change.

Setting Current Value Plain-English Meaning
DATASET_ID merve/folk-mythology-tales The Hugging Face dataset this project downloads.
CACHE_DIR ~/.cache/autoresearch/folk-mythology-tales Where the downloaded data and tokenizer are stored on your Mac.
RAW_FILENAME raw_train.parquet The original Hugging Face Parquet file after download.
TRAIN_FILENAME train.parquet The local training file created from the dataset.
VAL_FILENAME val.parquet The local validation file used to check model quality.
VAL_FRACTION 0.05 5% of usable rows are held back for validation.
VOCAB_SIZE 8192 The tokenizer learns up to 8,192 token IDs. This controls the model vocabulary size.
MAX_SEQ_LEN 2048 The model sees chunks of up to 2,048 tokens at a time.
TIME_BUDGET 300 seconds The training script trains for about 5 minutes per experiment.
EVAL_TOKENS 40 * 524288 The validation metric is computed over about 21 million tokens.
Important: I did not change the model architecture or training hyperparameters in train.py. The main work was changing the data preparation path in prepare.py.

What Was Evaluated

1. Preparation run

I ran uv run prepare.py. This confirmed that the code could download the Hugging Face file, create local train/validation files, and train the tokenizer.

Result Meaning
190,792 train rows Rows used to teach the model.
10,041 validation rows Rows held back to score the model after training.
vocab_size=8192 The tokenizer successfully learned an 8,192-token vocabulary.

2. Dataloader smoke test

A smoke test is a small, quick test that asks, “Does the basic thing work?” I loaded one training batch and one validation batch. Both returned tensors shaped [2, 128] on mps:0, meaning the data was successfully tokenized and moved to Apple Silicon’s Metal device.

3. Full training run

I ran uv run train.py. The model trained for the fixed 5-minute budget and then ran the validation metric.

Metric Observed Value Plain-English Meaning
val_bpb 1.840602 Bits per byte on validation text. Lower is better. This is the project’s final score for a run.
training_seconds 301.0 The actual measured training time, roughly the intended 5 minutes.
total_seconds 848.1 Total wall-clock time, including startup and validation.
total_tokens_M 5.2 The model trained on about 5.2 million tokens during the run.
num_steps 80 The optimizer updated the model 80 times.
num_params_M 11.5 The model has about 11.5 million trainable parameters.

Glossary

Dataset A collection of examples. Here, each example is a piece of folklore or mythology text.
Hugging Face A popular website for hosting machine-learning datasets and models.
Parquet A file format that stores tables efficiently. Think of it like a compact spreadsheet for programs.
Train split The portion of the data the model learns from.
Validation split Data held back during training so we can test whether the model learned useful patterns.
Tokenizer A tool that turns text into numbers. Models do math, so text must become numeric token IDs.
Token A chunk of text. It might be a word, part of a word, punctuation, or whitespace.
Vocabulary size The number of token IDs the tokenizer knows. This project uses 8,192.
Dataloader Code that feeds batches of prepared data into the model during training.
Batch A group of training examples processed together. Batches make training more efficient.
Tensor A block of numbers. In this project, batches become tensors before being sent to the model.
MPS Apple’s Metal Performance Shaders backend. It lets PyTorch use Apple Silicon GPU acceleration.
Parameter A number inside the model that changes during training. More parameters usually means more capacity.
Optimizer The algorithm that updates model parameters based on training errors.
Loss A number measuring how wrong the model is while training. Lower usually means better.
BPB Bits per byte. This repo’s validation score. Lower means the model predicts validation text better.
Smoke test A small test that checks whether the core path works before spending more time.

Mental Model

The whole flow looks like this: 

Hugging Face dataset
        ↓
Download Parquet file
        ↓
Keep clean text rows
        ↓
Split into train.parquet and val.parquet
        ↓
Train tokenizer
        ↓
Dataloader packs token batches
        ↓
train.py trains model
        ↓
Validation produces val_bpb score

That is the core loop behind many language-model data workflows: collect text, clean it, split it, tokenize it, feed it to a model, and evaluate on held-back data.
